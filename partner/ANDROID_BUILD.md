# Building the Goocart Partner APK in Android Studio

The native project is `partner/android/`, generated by `npx expo prebuild`.
Open **that folder** in Android Studio — not the repo root.

This is a separate app from the customer app in `customer/`: different package
name (`com.goocart.partner`), different keystore, different signing
properties. Never reuse the customer app's keystore here.

---

## Build a **release** APK, not debug

A **debug** APK does not contain your JavaScript — it downloads it from the
Metro dev server at launch. Install one without Metro running and you get a
red screen: *"Unable to load script."*

A **release** APK embeds the JS bundle and runs standalone. That is the one
you want.

**Android Studio:** open the *Build Variants* panel (left edge) → set `app`
to **release** → **Build → Build Bundle(s)/APK(s) → Build APK(s)**.

**Terminal:**

```bash
cd partner/android && ./gradlew assembleRelease
```

Output: `partner/android/app/build/outputs/apk/release/app-release.apk`

---

## 1. Point the app at your backend (do this first)

A built APK has no Metro server to discover a host from, so the backend URL
is compiled in from `partner/.env`:

```
EXPO_PUBLIC_API_URL=http://<your-lan-ip>:3001
```

Find your machine's IP with `ipconfig` (IPv4 under Wi-Fi). It changes when
you reconnect or switch networks — update `.env` if the app can't reach the
server.

For the phone to reach it:

- Phone and PC on the **same Wi-Fi**
- Backend running: `cd server && npm run dev`
- Windows Firewall allowing inbound port 3001 (choose *Private networks* when
  prompted)

**Changing `.env` requires a rebuild** — the value is baked in, not read at
runtime.

A real release needs a public **HTTPS** URL (e.g. the Render-hosted API).
Cleartext HTTP is enabled only so a build can talk to a LAN IP during
development.

## 2. Signing

Generate a keystore just for this app — do not reuse
`customer/android/app/goocart-release.keystore`:

```bash
keytool -genkeypair -v -storetype PKCS12 -keystore goocart-partner-release.keystore \
  -alias goocart-partner -keyalg RSA -keysize 2048 -validity 10000
```

Put the file at `partner/android/app/goocart-partner-release.keystore`, then
add to `partner/android/gradle.properties`:

```
GOOCARTPARTNER_UPLOAD_STORE_FILE=goocart-partner-release.keystore
GOOCARTPARTNER_UPLOAD_KEY_ALIAS=goocart-partner
GOOCARTPARTNER_UPLOAD_STORE_PASSWORD=<your-store-password>
GOOCARTPARTNER_UPLOAD_KEY_PASSWORD=<your-key-password>
```

Both files are **gitignored**.

- **Back up the keystore somewhere safe.** Lose it and you can never publish
  an update under the package name `com.goocart.partner` — Play Store would
  require a new listing.

Signing survives `expo prebuild` via `plugins/withReleaseSigning.js`, which
re-injects the config each time. Without it, prebuild would silently revert
release builds to the debug key.

## Installing on a phone

```bash
adb install -r android/app/build/outputs/apk/release/app-release.apk
```

Or copy the `.apk` to the device and open it (enable *Install unknown apps*).

---

## Regenerating the native project

`android/` is generated output. Re-running prebuild overwrites hand edits to
`AndroidManifest.xml` and `build.gradle` — configure through `app.json` and
config plugins instead so changes survive.

Prebuild also deletes files it did not create, so after a `--clean` run you
must restore:

- `android/app/goocart-partner-release.keystore` (from your backup)
- the `GOOCARTPARTNER_UPLOAD_*` lines in `android/gradle.properties`
- `android/local.properties` — Android Studio recreates this automatically

## Troubleshooting

| Symptom | Cause |
|---|---|
| Red screen, "Unable to load script" | Built **debug** instead of release |
| App loads but no data, network errors | `EXPO_PUBLIC_API_URL` wrong/stale, backend down, or phone on different Wi-Fi |
| Signed in but see an empty dashboard | Account's role isn't `DELIVERY_PARTNER` — ask an admin to add your email to `PARTNER_USER_EMAILS` on the server |
| `EBUSY ... rmdir android` during prebuild | A Gradle daemon holds the folder — stop it (`./gradlew --stop`) or close Android Studio |
| `SDK location not found` | Missing `android/local.properties`; opening the project in Android Studio creates it |
