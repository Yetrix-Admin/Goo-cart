# Building the Goocart APK in Android Studio

The native project is `customer/android/`, generated by `npx expo prebuild`.
Open **that folder** in Android Studio — not the repo root.

---

## Build a **release** APK, not debug

This matters. A **debug** APK does not contain your JavaScript — it downloads it
from the Metro dev server at launch. Install one without Metro running and you
get a red screen: *"Unable to load script."*

A **release** APK embeds the JS bundle and runs standalone. That is the one you
want.

**Android Studio:** open the *Build Variants* panel (left edge) → set
`app` to **release** → **Build → Build Bundle(s)/APK(s) → Build APK(s)**.

**Terminal:**

```bash
cd customer/android && ./gradlew assembleRelease
```

Output: `customer/android/app/build/outputs/apk/release/app-release.apk`

---

## 1. Point the app at your backend (do this first)

A built APK has no Metro server to discover a host from, so the backend URL is
compiled in from `customer/.env`:

```
EXPO_PUBLIC_API_URL=http://10.247.252.138:3000
```

`10.247.252.138` was this machine's Wi-Fi IP when the project was set up.
**It changes when you reconnect or switch networks.** Re-check with `ipconfig`
(IPv4 under Wi-Fi) and update `.env` if the app can't reach the server.

For the phone to reach it:

- Phone and PC on the **same Wi-Fi**
- Backend running: `npm run dev` in the repo root
- Windows Firewall allowing inbound port 3000 (choose *Private networks* when
  prompted)

**Changing `.env` requires a rebuild** — the value is baked in, not read at
runtime. A plain rebuild is enough; you do not need to re-run prebuild.

A real release needs a public **HTTPS** URL. Cleartext HTTP is enabled only so
a build can talk to a LAN IP during development.

## 2. Signing

`android/app/goocart-release.keystore` is already generated and wired up.
Credentials live in `android/gradle.properties`:

```
GOOCART_UPLOAD_STORE_FILE=goocart-release.keystore
GOOCART_UPLOAD_KEY_ALIAS=<your-key-alias>
GOOCART_UPLOAD_STORE_PASSWORD=<your-store-password>
GOOCART_UPLOAD_KEY_PASSWORD=<your-key-password>
```

Both files are **gitignored**. Two things to know:

- **Back up the keystore somewhere safe.** Lose it and you can never publish an
  update under the package name `com.goocart.app` — Play Store would require a
  new listing.
- **Change those passwords** before this goes anywhere real. They were generated
  for local development convenience.

Signing survives `expo prebuild` via `plugins/withReleaseSigning.js`, which
re-injects the config each time. Without it, prebuild would silently revert
release builds to the debug key.

## 3. Google Maps key (only affects the tracking map)

`AndroidManifest.xml` has a placeholder:

```xml
<meta-data android:name="com.google.android.geo.API_KEY"
           android:value="REPLACE_WITH_ANDROID_GOOGLE_MAPS_API_KEY"/>
```

Without a real key the app runs fine but the map on the order-tracking screen
renders **blank/grey**. Nothing else is affected.

To fix: create a key in Google Cloud Console with **Maps SDK for Android**
enabled, put it in `app.json` under `android.config.googleMaps.apiKey`, then
re-run prebuild. Editing the manifest directly gets overwritten.

## Installing on a phone

```bash
adb install -r android/app/build/outputs/apk/release/app-release.apk
```

Or copy the `.apk` to the device and open it (enable *Install unknown apps*).

---

## Regenerating the native project

`android/` is generated output. Re-running prebuild overwrites hand edits to
`AndroidManifest.xml` and `build.gradle` — configure through `app.json` and
config plugins instead so changes survive.

Prebuild also deletes files it did not create, so after a `--clean` run you must
restore:

- `android/app/goocart-release.keystore` (from your backup)
- the `GOOCART_UPLOAD_*` lines in `android/gradle.properties`
- `android/local.properties` — Android Studio recreates this automatically

## Troubleshooting

| Symptom | Cause |
|---|---|
| Red screen, "Unable to load script" | Built **debug** instead of release |
| App loads but no data, network errors | `EXPO_PUBLIC_API_URL` wrong/stale, backend down, or phone on different Wi-Fi |
| Blank grey map on tracking screen | Google Maps API key not set |
| `EBUSY ... rmdir android` during prebuild | A Gradle daemon holds the folder — stop it (`./gradlew --stop`) or close Android Studio |
| `SDK location not found` | Missing `android/local.properties`; opening the project in Android Studio creates it |
